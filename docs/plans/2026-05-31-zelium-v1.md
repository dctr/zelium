# Zelium V1 Implementation Plan

> **For Hermes:** Use the Kanban board to implement this plan task-by-task. Every coding task follows the `test-driven-development` skill: write a failing test first, run it and confirm RED, implement the smallest change, run GREEN, then run the relevant suite and commit.

**Goal:** Build Zelium V1: a self-hosted web UI for one or more Markdown vault folders, with Notion-like inline Markdown editing, collapsed editable frontmatter, autosave, and full page/folder operations.

**Architecture:** A TypeScript/Svelte single-page web client talks to a small TypeScript Fastify server. The server is the only component that touches the filesystem and exposes a constrained vault API rooted at `VAULT_DIR` or semicolon-separated `VAULT_DIRS`. The UI uses a vault-client abstraction so future Tauri Android/iOS/Linux/macOS/Windows apps can replace HTTP calls with native filesystem commands without changing editor components.

**Tech Stack:** TypeScript, Svelte + Vite, Fastify, Milkdown/ProseMirror for WYSIWYG Markdown editing, Vitest for unit/component tests, Playwright for UI tests. Future native packaging target: Tauri v2, not Electron.

---

## Product Decisions

- **Version 1 platform:** web UI only.
- **Startup roots:** `VAULT_DIR=/one/root` or `VAULT_DIRS=/one/root;/another/root`. If `VAULT_DIRS` is present it wins over `VAULT_DIR`.
- **Auth:** none inside Zelium. HTTP Basic Auth belongs in Caddy.
- **Storage:** app content is Markdown files only. No content database, no hidden metadata sidecar required for MVP.
- **Frontmatter:** YAML frontmatter is a top block, collapsed by default with a `>` disclosure marker, expandable and editable as raw YAML.
- **Editing:** autosave as the user edits, with visible save state and conflict protection.
- **File ops:** create, rename, move, delete pages and folders.
- **Live Codex safety:** tests and automated write verification must use temporary fixture vaults. A final read-only smoke test may point `VAULT_DIR=~/.hermes/codex`; do not modify the live Codex unless the user explicitly asks.

## Stack Rationale

Flutter was considered for the longer native-app ambition. For V1 web-only delivery, TypeScript/Svelte + a Tauri-ready adapter is the better starting point because Node/npm are already installed locally, the web UI can be implemented immediately, and Tauri provides a lean non-Electron path to mobile/desktop later. Revisit Flutter only if native UI fidelity becomes more important than shipping the self-hosted web app.

## API Contract

All paths sent by the client are vault-relative POSIX-style paths. The server maps them to native paths only after root validation.

```http
GET /api/health
GET /api/vaults
GET /api/tree?rootId=<id>
GET /api/page?rootId=<id>&path=<path.md>
PUT /api/page
POST /api/page
POST /api/folder
PATCH /api/node
DELETE /api/node
```

Types:

```ts
export type VaultRoot = {
  id: string;
  name: string;
};

export type TreeNode = {
  rootId: string;
  path: string;
  name: string;
  kind: 'folder' | 'page';
  children?: TreeNode[];
};

export type PageDocument = {
  rootId: string;
  path: string;
  markdown: string;
  frontmatter: string;
  body: string;
  etag: string;
};

export type SavePageRequest = {
  rootId: string;
  path: string;
  frontmatter: string;
  body: string;
  etag: string;
};

export type CreatePageRequest = {
  rootId: string;
  path: string;
  frontmatter?: string;
  body?: string;
};

export type CreateFolderRequest = {
  rootId: string;
  path: string;
};

export type MoveNodeRequest = {
  rootId: string;
  fromPath: string;
  toPath: string;
  kind: 'folder' | 'page';
};

export type DeleteNodeRequest = {
  rootId: string;
  path: string;
  kind: 'folder' | 'page';
};
```

Rules:

- Page paths must end in `.md`.
- Folder paths must not end in `.md`.
- Reject absolute paths, `..`, empty segments, NUL bytes, and Windows drive-prefix forms.
- Resolve existing paths with `realpath` and confirm they remain under the selected vault root.
- For create operations, resolve the parent directory and confirm the parent remains under the root before writing.
- Do not follow symlink escapes. A symlink inside a vault pointing outside the root is not a valid page/folder.
- `etag` is derived from file `mtimeMs` + size. `PUT /api/page` must reject stale `etag` with `409 Conflict`.
